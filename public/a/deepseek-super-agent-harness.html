DeepSeek Super Agent：真正值得看的，是「一切皆插件」的 Harness

同模型换九套编码 Agent，成本能差出一个数量级。Instacart 和 Box 的 CTO 都把票投给了 harness。

2026年11月5日 · 周四 AI news / DeepSeek Super Agent explainer DeepSeek · harness · agent

很多人把 DeepSeek 新开源的东西叫「Claude Code 的回答」。视频作者觉得，更值得盯的是它怎么被做出来的。

Super Agent 不是又一个聊天窗口。它听团队已经在用的地方：GitHub Issue / PR，以及飞书。有权限的人提需求后，它开 work item，在独立目录里干活，再带着 PR 回来。DeepSeek 自己说，这是研究原型，很多工程甚至是编码 Agent 写的。

底座是八月发布的 DeepSeek Harness（DSH）。口号很绝：一切皆插件。路由、工具注册、会话日志，连 Agent loop 本身都是插件，底下是叫 Cordis 的组合框架。两个关键能力：

  • 时间可组合：卸掉一个组件，它做过的注册会完整回滚
  • 空间可组合：组件声明依赖，运行时按依赖上下线

Frontier Harness Eval 用同一模型 Kimi K3、同一批 30 个任务，跑九套 harness。Codex 通过率 66.7%，DeepSeek creator 模式和 Claude Code 都是 63.3%，但单次成功任务成本大约 $3.28 vs $18.34。样本不大，方向很清楚：换 harness，成败和账单都会变。

Super Agent 的架构也很有意思：上层一个长驻 router 负责人和分发，下层 worker 各自隔离会话。外部触发先过确定性门禁（在不在白名单、有没有真正 @ Agent），过了才进模型。Worker 认领 ticket 后直接订阅那条对话，评论不再绕 router，他们测过，关掉这层后 router 决策量大约多 30%。压力测试里触发从每分钟 1 次拉到 40 次，批量处理后单次决策时间反而下降。结论有点反直觉：router 往往更适合轻模型，重模型留给 worker。

作者访谈过 Instacart 和 Box 的 CTO，两边都认为现阶段 harness 比模型更重要。视频收尾也留了清醒提醒：这是原型，安全问题（提示注入、凭据泄漏、跨设备权限）他们自己也承认没完全解决。

如果你只记住一句：别再只评模型。同一模型至少丢进两三个 harness 再下判断，不然你骂的可能是壳，不是芯。
