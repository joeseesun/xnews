Rauch：Vercel 内部那个「惊人有效」的安全 Agent，终于对外开放了

每行代码自动审计。他的判断很直白：你不能指望工程师记得装技能，或掷骰子赌第一版就安全。

2026年11月3日 · 周二 Guillermo Rauch security · agent · Vercel

Guillermo Rauch 等这一天很久了。

Vercel 内部有个安全 Agent，昵称叫 @hacker。Rauch 的原话是「astonishingly effective」：每一行代码都会被自动审计。现在，同样的能力对外开放了。打开之后，不管你的项目是不是部署在 Vercel 上，都可以挂到仓库上跑。

他为什么这么急着推？因为边界条件已经变了。

你不能只靠工程师「记得装一个安全技能」，也不能只靠 prompt 里写一句「请写得安全一点」，更不能赌模型第一次就吐出靠谱代码。安全要变成默认流水线，而不是人品考验。

配套产品是 Vercel Security Review（公测）。按官方说明，它挂在每次 GitHub push 上：扫变更、在 PR 留评论、进 Security 面板，也可以让 Vercel Agent 验证并直接提修复。扫描的是 diff，所以通常几秒结束，预览和生产部署都能跑。

Rauch 还特意点了一句：这套东西是安全团队自己做出来的。很多公司正忙着招人补安全编制；如果你想「把一个安全团队下载成软件」，这大概是今天最接近的形态。

我读完更在意的是分工。写代码的 Agent 越来越多，审代码的 Agent 如果不跟上，中间那截空档会变成默认攻击面。Rauch 这篇文章，其实是在说：安全也该产品化，而且要产品到「每 push 必审」。
